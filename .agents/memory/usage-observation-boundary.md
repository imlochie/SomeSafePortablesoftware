---
name: Usage observation boundary
description: How watch/usage data enters the control plane, what it can and cannot prove, and what it is never allowed to do.
---

Archive Assistant never plays media, so it never directly observes a watch. Every watch record is a provider claim and must be stored as an owner-scoped observation with provenance (provider, collection time, upstream record identity), alongside `plex_item` rather than above it. Ingestion is append-only and deduplicated on a stable observation identity. Sessions, aggregates, habits, and patterns are recomputable derivations carrying an evidence hash over their inputs, not remembered numbers.

**Why:** Providers differ sharply in what they retain, and the difference decides what is buildable. Plex keeps per-play rows in `metadata_item_views` indefinitely — including for deleted media — and exposes them via `/status/sessions/history/all` with `viewedAt>=` paging, so a years-deep backfill is available on first connect. Jellyfin natively keeps only current state in `UserDatas`; per-play history needs the Playback Reporting plugin, which trims past 12 months by default, and trimmed history is unrecoverable.

**The distinction that governs design is event truth versus session truth.** A history row proves *that* a play happened, with timestamp, account, and device. It does not carry that play's duration or stop position; duration exists only in pre-aggregated `/statistics/media` buckets, detached from individual plays, with finer buckets pruned over time. So watched-titles, rewatch, recency, time-of-day, and the owned-versus-watched funnel are backfillable, while session length, completion rate, and abandonment only accrue from the day live capture starts. Never compute the second group from backfilled data as if equivalent; surface a "collecting since" date instead.

**Governing principle:** when evidence cannot distinguish two explanations, preserve the ambiguity rather than manufacturing a transition.

**Ownership relation.** Because Plex history outlives deletion, every resolved observation carries a derived, recomputable ownership relation with four states: `currently_owned`, `previously_owned`, `departure_unconfirmed`, `never_matched`. Keep the last two distinct — `never_matched` means no evidence it was ever owned; `departure_unconfirmed` means evidence it was owned but insufficient evidence of when or how it left. Departure evidence has two grades: **exact** (an `archive_operation` delete/move/rename, with a timestamp) and **bounded** (present in snapshot A, absent in snapshot B, departure somewhere in that interval). A bounded departure is an interval and must never be rendered as a date. `file_record.scan_status = 'missing'` is not departure evidence at any grade — it is a read failure and maps to `departure_unconfirmed`. Elapsed time cannot distinguish a disconnected drive, an unavailable mount, a permissions failure, a transient error, and a deletion, so no `missing for N days → previously_owned` rule is permitted; an aged label such as `long_term_missing` may live *within* `departure_unconfirmed` and never upgrades to a departure claim. Library-state snapshots must interleave with watch history, or "I removed this" and "I stopped watching this" are indistinguishable. The snapshot interval is an epistemic resolution setting: it fixes the width of every bounded departure window, so choose it from operational cost and desired precision and expose the resulting resolution. Dead storage requires continuous presence, known observation coverage, and no recorded viewing — never `owned − watched`.

**Ingestion path.** API ingestion through the existing adapter is the default. Reading Plex's private `com.plexapp.plugins.library.db` is a deliberate, documented exception requiring concrete justification (for example, an unworkable backfill at 100k+ events). If taken, a single read-only importer owns Plex's internal schema and emits normalised observations; no service, contract, or UI may reference Plex table or column names. Writing to that file is permanently out of scope.

**Scope validation is an ingestion contract.** Plex history is server-wide, so ingestion validates scope — account, media type, library, Live TV/DVR exclusion, supported event types — and the resulting dataset carries its scope definition as part of its identity. An aggregate without its scope is a number without units: "you've watched 2,481 things" is unanswerable six months later if which accounts, libraries, and media types were counted was never recorded. Persist scope alongside every aggregate so a scope change appears as a recomputation rather than an unexplained discontinuity.

**How to apply:** Report which grade of history each provider actually supplies, and record observation coverage so a gap is distinguishable from genuine inactivity. Qualify every usage metric with its identity-resolution coverage denominator; retain unresolved observations rather than attributing them to a nearest match. Every metric declares the window its evidence covers, and backfilled and instrumented windows are never merged — "average session length since 2019" computed from 2026 instrumentation is the specific lie to prevent; state both windows or decline the claim. Treat a manual "mark watched" as a library-state claim in a separate evidence class — it writes no history row — and remember item-level `viewCount`/`lastViewedAt` read through the owner token report the owner, not the viewer. Sessionisation of history rows is versioned inference, not observation: where an observed live session and an inferred one overlap, observed duration wins and the aggregate records which it used. Usage findings stay advisory — they may contribute evidence to a recommendation but must never shorten the path from observation to file mutation, and a never-watched signal must carry its coverage qualification into any review record. Treat watch history and device identifiers as the most sensitive data in the product: owner-isolated, excluded from logs, explicit retention class.
