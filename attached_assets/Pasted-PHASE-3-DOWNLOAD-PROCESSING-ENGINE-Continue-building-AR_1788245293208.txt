PHASE 3: DOWNLOAD + PROCESSING ENGINE

Continue building ARCHIVE ASSISTANT from the existing Phase 1 and Phase 2 implementation.

IMPORTANT:

Do NOT rebuild the application.

Do NOT remove or replace working Phase 1 or Phase 2 functionality.

Do NOT implement Plex integration yet.

Do NOT implement the AI provider yet.

This phase turns the existing media inspection system into a real persistent local download and processing system.

The application must remain Windows-first and local-first.

==================================================
GOAL
==================================================

Build a reliable background media job system capable of:

- preparing downloads
- downloading with yt-dlp
- tracking progress
- handling separate video/audio streams
- using FFmpeg for muxing when required
- verifying completed media
- managing temporary files
- moving completed media into configured destinations
- surviving application restarts
- retrying failed jobs
- cancelling jobs
- maintaining a persistent history

The application should behave like a small local media processing daemon.

The UI must remain responsive while downloads and processing occur.

3. FORMAT SELECTION
==================================================

A download job should be able to use the recommendation generated by the Phase 2 quality-selection engine.

Do NOT duplicate the quality-selection algorithm inside the downloader.

The downloader should receive a selected source specification.

- video-only + audio-only
- HLS
- DASH
- direct media
- other yt-dlp-supported protocols

When separate video and audio are required, allow yt-dlp/FFmpeg to combine them.

Do not leave corrupted partial files in the archive.

8. CONCURRENCY
==================================================

Implement configurable concurrent downloads.

Default:

Allow:

1
2
3
4

Do not start more than the configured number of simultaneous downloads.

Processing jobs should also respect system resources.

Do not start many simultaneous FFmpeg transcodes on a 16 GB laptop.

Prefer a processing concurrency of 1 by default.

==================================================
9. PAUSE / RESUME
==================================================

Implement pause/resume where yt-dlp and the source protocol support it reliably.

If true pause/resume is not possible for a specific source:

- clearly report this
- safely cancel the current process
- preserve enough state to restart

Never pretend a job is paused if the process has actually been terminated.

==================================================
10. CANCELLATION
==================================================

Implement safe cancellation.

When the user presses:

[CANCEL]

the application should:

1. stop the underlying process
2. stop child processes where necessary
3. update job state
4. clean temporary partial files when safe
5. preserve the job in history as CANCELLED

Do not kill unrelated processes.

==================================================
11. RETRIES
==================================================

Implement retry handling.

Default:

3 retries

Make configurable.

Retry appropriate transient failures such as:

network interruption
temporary source error
connection timeout

Do not endlessly retry permanent failures such as:

unsupported source
DRM
invalid URL
missing permissions

Use exponential backoff.

==================================================
12. RESUMABLE DOWNLOADS
==================================================

Use yt-dlp's supported resume behavior where possible.

If an application restart occurs during a download:

The database must retain the job.

On startup:

detect jobs that were previously:

DOWNLOADING
PROCESSING
VERIFYING
MOVING

Mark them as:

RECOVERY_REQUIRED

Then inspect their state and determine whether they can safely resume.

Do not automatically destroy partial downloads.

Provide:

[Resume]
[Restart]
[Cancel]

when appropriate.

==================================================
16. MEDIA VERIFICATION
==================================================

After download/processing:

run media verification.

Use FFmpeg/ffprobe.

Check:

- file exists
- file size > 0
- container readable
- duration available
- video stream exists when expected
- audio stream exists when expected
- resolution
- codec
- stream integrity where practical

A completed download must NOT be marked COMPLETE merely because yt-dlp exited successfully.

Verification must succeed first.

If verification fails:

FAILED

with a useful explanation.
