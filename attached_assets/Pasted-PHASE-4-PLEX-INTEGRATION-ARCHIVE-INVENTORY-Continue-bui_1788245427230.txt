PHASE 4: PLEX INTEGRATION + ARCHIVE INVENTORY

Continue building ARCHIVE ASSISTANT from the existing Phase 1, Phase 2 and Phase 3 implementation.

IMPORTANT:

Do NOT rebuild the application.

Do NOT remove working functionality.

Do NOT replace the existing database architecture.

Do NOT break the existing download engine.

This phase adds the Plex integration and creates the application's real archive inventory.

The application must remain:

- Windows-first
- local-first
- privacy-conscious
- modular
- safe with existing media

==================================================
GOAL
==================================================

Connect ARCHIVE ASSISTANT to the user's Plex Media Server.

The application should be able to understand:

- what media exists in Plex
- which libraries exist
- where media files are located
- technical quality of existing files
- what has recently been added
- what files are associated with each Plex item
- what media could potentially be upgraded later

The application must NOT copy media files into itself.

The application stores metadata about the user's media.

The actual media remains where it already lives.

==================================================

The frontend should communicate only with the local backend.

==================================================
3. TOKEN STORAGE
==================================================

Do not store the Plex token in React state permanently.

Do not put it in frontend JavaScript.

Do not expose it through an API response.

Store it securely in the local backend configuration.

If secure OS credential storage is practical on Windows, use it.

Otherwise use an appropriately protected local configuration mechanism.

Never write the token to logs.

==================================================
22. REMOVED ITEMS
==================================================

If an item disappears from Plex:

Do NOT immediately hard-delete the local database record.

Mark it:

REMOVED_FROM_PLEX

Keep historical information.

This allows future archive history and auditing.

If the item later reappears:

restore its active status.
