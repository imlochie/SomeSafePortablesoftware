==================================================
CORE OBJECTIVE
==================================================

The application should now be able to answer questions such as:

"Do I already have this?"

"Is this already in Plex?"

"Is this probably a duplicate?"

"Is the available source better than my existing copy?"

"What quality do I currently have?"

"Which version should I keep?"

"Which items in my archive might be worth upgrading?"

"Did I already download this?"

"Is this file already waiting in the queue?"

The answers must come from actual application data.

Never invent archive information.

2. NORMALIZED MEDIA IDENTITY
==================================================

Create a normalized media identity system.

A media identity should consider:

- title
- year
- show title
- season
- episode
- duration
- source ID
- Plex GUID
- normalized filename
- uploader where useful

Do not rely on filename alone.

Do not rely on title alone.

Use multiple signals.

==================================================
3. TITLE NORMALIZATION
==================================================

Create a robust title normalization function.

Normalize:

- capitalization
- punctuation
- whitespace
- underscores
- hyphens
- common filename separators

Preserve meaningful numbers.

Examples:

"4 Your Eyez Only"

"4_Your_Eyez_Only"

"4-Your-Eyez-Only"

should be recognized as likely the same title.

Do NOT aggressively strip meaningful words.

Do not turn unrelated titles into false matches.

4. MATCH SCORING
==================================================

Create a deterministic match score.

Consider:

Title similarity
Year similarity
Duration similarity
Plex GUID match
External source ID match
Show identity
Season
Episode
Filename similarity

Return:

matchScore
matchType
reasons

Types:

EXACT_MATCH
LIKELY_MATCH
POSSIBLE_MATCH
NO_MATCH

Example:

EXACT_MATCH

Reasons:
- identical source ID
- identical Plex GUID

or:

LIKELY_MATCH

Reasons:
- title similarity 96%
- year identical
- duration within 8 seconds

The matching algorithm must be deterministic and testable.
